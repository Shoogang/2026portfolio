设计、产品、算法的第一次共同决策

为什么需要共决

Agent 模式到来后，我梳理出三组议题——看似是 UI 问题，实则每一个都牵动三方：

  • 算法思考在哪一层产生？
  • 产品这个信息对用户有价值吗？
  • 设计如何呈现用户能理解？

我主动发起三方评审——梳理议题 → 方案对比 → 共同决策

设计主导的结构化重构

重构动机

V1 稳定后，我观察到 Plan 的核心价值被执行信息淹没——用户最关心的"任务进展"反而最难看到。于是主动发起重构。

竞品研究
Coze Manus Workbuddy Codex

形成 3 个行业共识：

  • 01Plan 应前置
  • 02Plan 应可干预
  • 03Plan 应可折叠
V2 方案
计划确认前置卡片
① 前置卡片 ② 可展开 ③ 可调整 ★ 固定锚点
四个核心改动
  1. 前置确认卡片产品推动

    用户先看全貌再决定执行

  2. 可展开/收起的步骤

    控制信息密度

  3. 可手动点击调整

    从被动接受变为主动参与

  4. Plan 固定在输入框上方★ 我主导

    大模型思考输出量大时，用户最关心的"任务进展"被淹没。将 Plan 作为持久视觉锚点，进展始终可见。

我们的差异化

在行业共识之上，核心差异化是将 Plan 固定为输入框上方的持久视觉锚点——大模型思考输出量大时，用户始终能看到任务进展

业务催着走时要能快速上线，业务稳定后更要主动回头打磨
设计的纵深，不在第一版，而在第二版

H. 08
Track 01 · 问题发现与迭代

一期上线后：数据没达预期
二轮实地调研

一期上线后，使用数据没有达到预期——销售员依然大量使用老 ERP 完成报价。
我必须回到现场，找出真正的原因：不是用户不会用，而是这套设计根本不符合他们的真实工作场景
二轮调研 · 两个关键发现
发现 01
小屏笔记本 · 信息密度太低
现场观察
  • 货代销售员普遍使用 1366×768 小屏笔记本
  • 新方案的"宽松布局"在小屏上显得过于稀疏
  • 老 ERP 信息密度更高，熟手操作反而更快
重新审视
✗ 错：为了"易读"牺牲"密度" ✓ 对：高频任务面向熟手——效率优先于易读性
发现 02
报价高频场景不全覆盖
现场观察
  • 真实销售工作不是"一问一答"，而是"多轮议价"
  • 初次报价经常是"批量报几条路线让客户比较"
  • 多轮询价时，用户的表达是口语化的 NLP 增改条件
重新审视
✗ 错：只设计了"单次单报价"路径 ✓ 对：支持批量报价 + 多轮 NLP 智能识别
我做错了两个判断——但这次"假设→验证→推翻→重做"的闭环，
才是资深设计师真正的标志性能力
